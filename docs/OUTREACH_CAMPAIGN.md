## Core proof

The campaign tests one proposition: a useful evening Field Guide can produce
qualified discovery on X and an observable return toward the canonical
publication without weakening reader privacy or either daily edition.

| Proof question | Earliest credible evidence | Invalid substitute |
| --- | --- | --- |
| Does the Field Guide attract qualified attention? | An approved source card or reply receives a relevant target-author interaction | Impressions alone |
| Does discovery produce return? | The selected privacy-safe return path records its declared return event | RSS intent, a profile visit, or an unknown site-return value |
| Is the lane sustainable? | Complete approval and outcome receipts stay within the staffed time budget | Filling a posting quota |
| Does the campaign preserve trust? | No unsupported claim, privacy failure, policy signal, or material correction | Silence about incidents |

Canonical edition quality wins every scheduling conflict. Zero source cards
and zero replies are correct when no item clears the quality and approval gates.

## Privacy-safe observable return path

RSS remains a canonical delivery surface, but the current `rss_follow_intent`
fallback is unobservable and cannot satisfy the return gate. X impressions,
profile visits, follower changes, public page availability, and an unknown site
return are also invalid substitutes.

The selected path records X's provider-reported `Link clicks` aggregate for one
public post containing one exact immutable DDB edition URL. The closed receipt,
schema, validator, inactive ledger, and read-only preflight are recorded in:

- `operations/outreach-observable-return-validation-receipt.json`;
- `operations/schemas/outreach-observable-return-receipt-v1.schema.json`;
- `operations/validate_outreach_observable_return.py`; and
- `operations/outreach-observable-return-ledger.json`.

The implementation:

1. exposes a defined return event that can actually be observed;
2. records an implementation receipt and a validation receipt;
3. collects no personal or spiritual data, raw IP address, fingerprint, or
   cross-site identifier;
4. does not activate email, analytics, or a community feature under this
   amendment;
5. remains separate from the official first-1,000 collector; and
6. has an explicit stop and rollback path.

The receipt records click events, not people. A Link click is not a verified
page load, unique visitor, repeat reader, RSS follow, subscriber, or first-1,000
participant. The implementation therefore preserves site return and the
official first-1,000 value as unknown.

The path is locally implemented and validated only. No campaign source card,
reply, tracker, reader request, or new provider action occurred. The campaign
remains blocked pending exact-head release, a current X readiness receipt, and
the later exact activation decision.

## X reply law

Spark's `daicc-ddb-autopost` remains the sole canonical broadcaster. This
campaign does not migrate or duplicate it.

- Replies may run only on staffed days and only when a candidate clears
  `docs/X_REPLY_PLAYBOOK.md`.
- Every reply binds approval to one parent URL and exact text, expires after 60
  minutes, and is manually posted once by David through the official X UI.
- The allowed daily range is zero through four. Four is an absolute ceiling,
  not a quota. A fifth reply requires a new founder amendment.
- Proactive replies contain no DDB link during the first 30 operating days
  unless the parent author requests the source or a claim requires it.
- No X API reply credential, browser scripting, scraping, automated browsing,
  paid read, automated reply, like, follow, quote, message, or list mutation is
  authorized.

The X Manager and canonical broadcaster remain separate from manual campaign
replies. No private API budget, X Pro deck, Radar result, or monitor output
authorizes a reply.

## Approval, stop, and rollback

David separately approves every source card and every reply. Silence is
rejection. Approval cannot be reused after the source edition, parent, text,
asset, account, or context changes.

Stop immediately on an account warning, credential concern, hidden or
probable-spam reply, unsupported claim, material correction, private-data
exposure, weakened edition, duplicate or wrong-account action, return-path
privacy or validation failure, or any unapproved external action or cost.

Rollback means stop campaign preparation and publication, preserve the
incident receipt, correct or remove the affected X item through the official
UI when separately authorized, and change only the smallest declared variable
after review. Never rewrite the canonical archive to hide an error.
